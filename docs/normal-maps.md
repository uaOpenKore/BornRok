# Нормал-мапы (карты нормалей) — #107

Поддержка карт нормалей для рельефного освещения по солнцу карты (RSW). Реализовано
для **именованных текстур**: моделей (RSM) и земли (GND). Для спрайтов персонажей —
неприменимо (см. раздел «Спрайты»).

## Соглашение об именах

Карта нормалей — это файл-«сосед» диффузной текстуры: то же имя, расширение заменено
на `_n.png`.

| Диффузная текстура | Карта нормалей |
| --- | --- |
| `data/texture/foo.bmp` | `data/texture/foo_n.png` |
| `data/model/wall.tga` | `data/model/wall_n.png` |

Функция построения пути — `normalMapPath()` в `Client/src/formats/ImageIO.cpp`.

Файл можно положить как в GRF, так и «россыпью» — свободные папки перекрывают GRF
(см. `Vfs::read`), поэтому HD-набор нормалей можно добавлять, не переупаковывая архив.

## Формат

- **Tangent-space normal map**: RGB кодирует вектор нормали XYZ (стандарт: плоскость =
  `(128, 128, 255)`).
- Любой поддерживаемый формат по магии файла, но по соглашению — **PNG** (`_n.png`).
- Любое разрешение (ограничение — только `maxTextureSize` GPU); строится мип-цепочка,
  так что рельеф не «шумит» на удалении.

## Как это работает

1. При загрузке карты/модели рядом с каждой диффузной текстурой ищется `_n.png`.
   Если файла нет — подставляется «плоская» текстура `(128,128,255)`, и эффект
   выключается (см. флаг ниже). **Без карты кадр рисуется байт-в-байт как раньше.**
2. Направление солнца берётся из RSW (`longitude`/`latitude` → единичный вектор,
   та же формула в `ModelRenderer` и `MapRenderer`).
3. В шейдере нормаль из карты переводится в мировое пространство через тангент-базис
   и освещается по `N·L`.

### Земля (`vs_ground` / `fs_ground`)

- Сэмплер `s_nrm` — **слот 2** (слот 1 занят лайтмапой).
- У вершин земли есть нормаль грани, но **нет тангента** — он выводится в `vs_ground`
  из нормали и фиксированной мировой оси (для плоских тайлов это ось Z, для стен —
  корректный горизонтальный тангент; точный «поворот» не важен, см. следующий пункт).
- Бамп применяется как **отношение** `N·L` возмущённой нормали к `N·L` геометрической.
  Плоский тексель `(0,0,1)` даёт отношение 1 — яркость тайла не меняется, подсвечивается
  только реальный рельеф. Это сохраняет общую яркость карты.

### Модели (`vs_model` / `fs_model`)

- Сэмплер `s_nrm` — **слот 1**.
- Тангент есть в вершинах модели (`a_tangent`), мировой базис строится в `vs_model`.

### Общие юниформы

- `u_nrmParams`: `x` = есть карта (1/0), `y` = сила бампа (сейчас 1.0).
- `u_lightDir`: направление на солнце (нормализованное).

## Спрайты — почему не поддерживаются

Спрайты персонажей/мобов/NPC собираются в рантайме из `.spr` (индексированные кадры →
RGBA в память) и **не имеют файла-текстуры на диске**, к которому можно приложить
`_n.png`. Сам формат `.spr` хранит только цвет — ни нормалей, ни тангентов. Кроме того,
актёры рисуются общим шейдером `fs_sprite3d`, который делят вода и тени (форк опасен).
Поэтому файловое соглашение `_n.png` на спрятах неприменимо; полноценные нормали для
спрайтов потребовали бы отдельного пайплайна (companion-формат нормалей на кадр + свой
шейдер) и контента, которого нет. По решению — вне рамок #107.

## Как проверить

1. Экспортировать диффузную текстуру тайла/модели, сделать из неё карту нормалей
   (например, плагином в редакторе), сохранить как `<имя>_n.png`.
2. Положить рядом с диффузной (в GRF или свободной папкой `data/texture/…`).
3. Запустить клиент на этой карте — при движении солнца/камеры на поверхности должен
   появиться рельеф. Убрать файл — картинка вернётся к прежней.
