# Аудит портируемости клиента uaRO

> Задача #99. Оценка готовности к портам: Windows ARM, macOS, SteamOS/Linux, Android,
> iOS/iPadOS, консоли (Xbox/PS5/Switch). Проверено по факту: какие зависимости и где в коде
> завязаны на платформу.

## Главный вывод

Кодовая база **спроектирована портируемой**: чистый C++ + SDL3 (окно/ввод/ФС) + bgfx
(рендер). Платформо-зависимый код **строго изолирован** в трёх местах, в игровую/рендер/сетевую
логику Win32 не течёт. Рендер — через bgfx (D3D11/12, Metal, Vulkan, GLES), окно/ввод/ФС —
через SDL3. Свои форматы (GRF/SPR/ACT/GAT/GND/RSW/GR2) — переносимый C++.

## Зависимости сборки

| Зависимость | Назначение | Переносимость |
|---|---|---|
| **SDL3** | окно, ввод, файловая система, (позже звук) | Win/macOS/Linux/iOS/Android — первый класс; консоли — приватные порты |
| **bgfx / bx / bimg** | рендер | D3D11/12, Metal, Vulkan, OpenGL/GLES; консольные бэкенды есть, но под NDA |
| **ZLIB** | распаковка GRF | везде |
| **Threads** (std) | потоки | везде |
| **stb_image / stb_truetype** | картинки/шрифты (header-only) | везде |
| `ws2_32` | сокеты Windows | только под `#ifdef _WIN32`; на остальных — BSD-сокеты |

Аудио-библиотек **нет** (оригинальные mss32/bink/ijl15/granny2 в нашей реализации не
используются — свои парсеры). Когда добавим звук — брать SDL_audio (переносимо), не mss32.

## Где живёт платформо-зависимый код (всё остальное — платформо-нейтрально)

| Файл | Что | Готовность |
|---|---|---|
| `net/Socket.cpp/.hpp` | TCP-сокет: Winsock (`#ifdef _WIN32`) ↔ BSD-сокеты | ✅ уже абстрагировано; BSD-ветка работает на macOS/Linux/iOS/Android/консолях |
| `platform/sdl/SdlPlatform.cpp` | окно/ввод/ФС через SDL3; `_WIN32` только для имени pref-каталога | ✅ SDL3 кроссплатформенный; pref-dir через `SDL_GetPrefPath` |
| `core/thread/ThreadRole.cpp` | имя потока: ветки `_WIN32`/`__APPLE__`/`__linux__` | ⚠️ для Android/iOS добавить ветку (`pthread_setname_np`, как linux/apple) — минор |
| `render/Shader` | компиляция шейдеров по бэкенду (dx11/spirv/glsl) | ⚠️ добавить профили Metal (iOS/macOS) и консольные; механизм мультипрофильный уже есть |

## По платформам

**1. Почти даром (пересборка под таргет):**
- **Windows ARM** — собрать под ARM64, D3D11/12. Тривиально.
- **macOS** — десктоп, SDL3 + bgfx Metal. Добавить Metal-профиль шейдеров, подпись. Легко.
- **SteamOS / Linux / Steam Deck** — core уже собирается под Linux; нативный билд идёт. Для Deck — геймпад-UI.

**2. Реальная, но штатная работа:**
- **Android** — SDL3 нативно, bgfx GLES/Vulkan. Нужно: JNI-бутстрап, упаковка GRF в asset/OBB,
  ветка ThreadRole, и главное — **тач-управление**.
- **iOS / iPadOS** — SDL3 + bgfx Metal. Нужно: Apple Developer, подпись, ревью App Store,
  тач-UI, Metal-шейдеры. GRF — это данные (не исполняемый код), правилам Apple не противоречит.

**3. Закрытые (Xbox/PS5/Switch):**
Движок их умеет (bgfx: D3D12X/GNM/NVN; SDL — консольные порты), НО SDK под NDA (нужны
девкиты, ID@Xbox / Sony / Nintendo NDP, одобрение), жёсткая сертификация (геймпад-only UI,
suspend/resume, аккаунты платформы), а MMO-клиент к приватному серверу сложно сертифицировать.
Это не задача кода, а бизнес/лицензии — отдельный большой проект.

## Сквозная работа №1 для всего, кроме десктопа — управление

RO заточен под мышь+клавиатуру. Под тач и геймпад нужна переработанная схема ввода
(эмуляция курсора / радиальные меню / контекстные действия). Это самая большая реальная
инженерная работа. Слой ввода у нас уже абстрагирован (`platform/Input.hpp`), так что точка
расширения есть.

## Прочее

- **Кодировки**: cp1251 в чате — это просто работа с байтами, на всех платформах ок.
- **Пути/файлы**: через `SDL_GetBasePath`/`SDL_GetPrefPath` — кроссплатформенно.
- **Эндианность**: все парсеры читают little-endian явно (ByteReader) — ARM/консоли ок.

## Итог

Под группы 1–2 (Win ARM, macOS, SteamOS, Android, iOS) порт **реалистичен**: слой `platform/`
чистый, утечек Win32 в логику нет. Основные трудозатраты — не код движка, а **тач/геймпад-UI** и
платформенная обвязка (подпись/стор/упаковка ассетов). Группа 3 (консоли) упирается в
лицензии/девкиты/сертификацию, а не в код.
