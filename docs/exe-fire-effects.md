# Как оригинальный uaRO.exe рисует огонь и кодовые эффекты карты (#32)

> Источник: дизассемблирование `uaRO.exe` (PE32 x86). Разбор по просьбе Сергея —
> «пройдись по спецэффектам в ЕХЕ, может поймёшь как они огонь рисуют».

## Главный вывод

Огонь факелов, дым, светлячки, туман подземелий — это **НЕ `.str`-эффекты**. Система
`CEffect::Initialize` (0x005c2630) — это switch на **166 `.str`-эффектов**, и в нём
**только скилловые/статусные** эффекты (Firewall, Meteor, StormGust, статусы и т.п.);
факела/дыма/огня карты там нет вообще. Проверено: диспетчер по EFFECTID для id 44/45/47
уходит в **default-ветку 0x005c30f6**, то есть «кодовый» (процедурный) эффект.

Кодовые эффекты карты рисуются **процедурным движком billboard-частиц** — тем самым, что
в GRF описан в `effecttool/effecttoolutil.lub`. Частицы — это спрайты `\particle1..7.spr/.act`
плюс отдельные текстуры-биллборды из папки `data/texture/effect/`.

## Текстуры кодовых частиц (реальные имена из exe)

- **Огонь**: `effect\FireRing.tga`, `effect\fire_ivy.bmp`, `effect\i_p_FIRE.tga`
- **Дым/облака**: `effect\smoke.tga`, `effect\cloud1/2/4/11.tga`
- **Туман**: `effect\fog1/2/3.tga`
- **Искры/электро**: `effect\elec1.tga`, `effect\flare%d.bmp`
- **Стихийные «иероглифы»**: `effect\i_p_{FIRE,WATER,WIND,EARTH,SAINT,DARK,TELE}.tga`
- **Спрайты частиц**: `\particle1.spr`..`\particle7.spr` (+ одноимённые `.act`)

## Как устроен эмиттер (пример FireRing, 0x005cd8c0)

Метод инициализации кодового эффекта заполняет поля глобальной структуры эффекта
(`[0x007710a8]`) числовыми параметрами и грузит текстуру-биллборд через загрузчик
`0x0040c590`:

```
mov [eff+0x2dc], 0x40b66666   ; размер частицы  = 5.7
mov [eff+0x2e8], 0x40b66666   ; (тот же 5.7)
mov [eff+0x2bc], 0xc1900000   ; высота/скорость = -18.0
... fmul [0x69fa68]           ; коэффициент затухания = -0.4
push 0 / push "effect\FireRing.tga"
mov ecx, 0x6ee3c8 / call 0x0040c590   ; загрузка текстуры биллборда
```

То есть каждый кодовый эффект = набор float-констант (размер, скорость/высота подъёма,
затухание альфы, число частиц в поле `+0x1b8`) + одна текстура-биллборд, отрисованная
аддитивно. Никаких `.str` и никаких данных из сервера — всё зашито в exe.

## Мастер-таблица длительностей `0x6d9100` — какие RSW-id оригинал ВООБЩЕ рисует

`CEffect::Initialize` в самом начале делает `ecx = [effectId*4 + 0x6d9100]` — это
**таблица длительности эффекта (мс) по effectId**. Значение `0` = эффект в этом exe
**не реализован** (id новых клиентов). Это отвечает на вопрос «каких эффектов не хватает»:
их часто НЕ не хватает — оригинал сам их не рисует.

Проверка топовых RSW-id по гистограмме 924 карт:
- **Рисуются** (dur>0): 47 факел=250, 44 дым=50, 45 светлячок=100 — **у нас уже есть ✅**
- **dur=0 → оригинал НЕ рисует** (и мы правильно игнорируем): **687, 688, 689, 690, 691,
  693, 694, 700, 702, 703, 710, 713, 714, 821, 838, 846, 946, 974** — весь частый
  «подземельный» диапазон 687–974.
- **Реализованы, но у нас ещё нет** (dur>0):
  - `.str`-типа: **109 = `Bubble%d.str`** (пузыри — подводные карты bif_fild), **110 =
    `GasPush.str`**, **199 = `Pong%d.str`**. Это looping-`.str`; `%d` = мультикадр →
    рисуется через `effectFxSeq`/`playEffectSeq`, а не одиночный `effectFxStr`.
  - кодовые (процедурные частицы, эмиттер в render-switch CEffect): **231, 247, 307,
    349, 353, 358, 360, 558** (dur 999…99999999 = постоянные амбиенты подземелий).

Итого «по всем dungeon-эффектам»: 90% частых id оригинал не рисует вовсе; реальный
остаток — 3 `.str`-амбиента (Bubble/GasPush/Pong) + ~8 кодовых, каждый требует
per-id снятия параметров из render-метода CEffect.

## Что это значит для нашего клиента

У нас факела уже рисуются (`torch_01` спрайт, `spawnMapEffects`), а дым(44)/светлячки(45)/
искры(165) — уже кодовыми частицами через `Particles.hpp` + аддитивный проход
`drawSkillParticles`. Совпадает с движком оригинала. Чтобы добить **остальные частые
кодовые id подземелий** (по гистограмме 924 карт: 690/691/693/946/713/714/702/703/710/199/
322/358/…), нужно для каждого id дизассемблировать его эмиттер в exe (тем же способом:
найти ref на его текстуру → снять float-параметры) и воспроизвести через нашу
`AmbientEmitter`. Угадывать текстуру по id НЕЛЬЗЯ (правило «эффекты только из реального
источника») — только точечный разбор per-id.
