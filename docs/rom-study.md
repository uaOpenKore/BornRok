# Изучение RoM (Ragnarok Origin) — #110

Цель задачи #110: научиться подтягивать **3D-сущности из Ragnarok Origin** (мобильная
игра Gravity на Unity) в наш клиент — через промежуточный формат **glTF**. Это даёт
более детальные 3D-модели персонажей/мобов/объектов взамен/в дополнение к классическим
2D-спрайтам RO.

> Статус: это **изучение формата и проектирование пайплайна**. Самого архива ассетов
> РоМ на рабочей машине сейчас нет (Google Drive-ссылку Sergio присылал в чат —
> нужно переслать, чтобы сделать конкретную инвентаризацию ассетов). Ниже — то, что
> можно установить и спроектировать без архива.

## 1. Формат ассетов РоМ (Unity)

RoM собран на **Unity**, поэтому 3D-контент лежит не отдельными `.fbx`, а внутри
**Unity AssetBundle** — контейнеров движка:

- Расширения бандлов: `.ab`, `.unity3d`, `.bundle` или вовсе без расширения /
  с обфусцированными именами (хеши).
- Внутри — сериализованные Unity-объекты: `Mesh`, `SkinnedMeshRenderer`,
  `Texture2D`, `Material`, `AnimationClip`, `Animator`, `GameObject`/`Transform`.
- Сжатие блоков: **LZ4** (по умолчанию) или **LZMA**.
- Возможна **кастомная шифровка/сигнатура** бандлов (частая практика мобильных
  RO-клиентов Gravity). Это проверяется по первым байтам архива — если магия не
  `UnityFS`, значит поверх наложена своя обёртка/XOR/крипта, и её надо снять первой.
  **Требует проверки на реальном архиве.**
- На Android ассеты обычно в `APK` + `OBB` (`assets/bin/Data/...` или отдельные
  бандлы). Если Sergio прислал уже распакованный набор — этот шаг пропускается.

## 2. Тулчейн извлечения

Извлекать 3D из Unity-бандлов в glTF/FBX/PNG:

- **AssetStudio / AssetStudioMod** (GUI, Windows) — вынимает Mesh, Texture2D,
  AnimationClip; экспорт мешей в `.fbx`/`.obj`, текстур в `.png`.
- **AssetRipper** — реконструирует полноценный Unity-проект (материалы, префабы,
  анимации), удобно для сложных сцен.
- **UnityPy** (Python) — скриптовое извлечение; удобно для пакетной автоматизации
  (пройтись по всем бандлам, вынуть Mesh+Texture+AnimationClip, сконвертировать в
  glTF). Наш предпочтительный путь для автоматизации, т.к. кроссплатформенно и
  скриптуется.
- Конвертация в **glTF**: из FBX — через `FBX2glTF` (Facebook) или Blender-экспорт;
  из UnityPy-мешей — напрямую собрать glTF (`pygltflib`).

Итог пайплайна оффлайн (контент-мейкер): `Unity bundle → (расшифровка) → Mesh/Tex/Anim
→ glTF (.glb) + PNG-текстуры`. Клиент грузит уже **готовый .glb** — Unity-рантайм в
клиент не тащим.

## 3. Что внутри (3D-сущности РоМ)

Ожидаемый состав (уточнить по архиву):

- **Персонажи (джобы)**: skinned mesh (низкополигональный, toon-styled) + скелет +
  набор `AnimationClip` (idle/walk/attack/…). Материал обычно albedo + иногда
  normal/emission, часто toon-рамп.
- **Мобы**: то же — skinned mesh + анимации.
- **Объекты/пропсы**: статические меши + текстуры.
- **Карты**: террейн + пропсы (скорее всего вне рамок первого шага — начинать
  разумно с одиночных сущностей).

## 4. Путь импорта в наш клиент

Клиент — bgfx, не Unity. Модели грузятся в простой меш-стуктуре и рисуются
`ModelRenderer`. Что уже есть (на что опираемся):

- `Client/src/formats/Gr2.*` — парсер 3D-моделей мобов RO в `Gr2Mesh`
  (`positions/normals/uvs/indices + texture`) → `Gr2Model`. Это ровно тот
  «плоский меш», который умеет загружать рендер.
- `Client/src/game/ModelRenderer.*` — заливка мешей в bgfx, освещение по солнцу RSW,
  **нормал-мапы** (`s_nrm`, см. [normal-maps.md](normal-maps.md)) — PBR-основа под HD.
- `Client/src/formats/Rsm.*` — статические модели RO (здания).

**Чего нет:** загрузчика glTF и скелетной анимации (skinning) в рендере (`Gr2Mesh`
пока хранит только базовую позу — normals/uv, без костей).

### Предлагаемая архитектура #110

1. **`formats/Gltf.*`** — загрузчик glTF/GLB на **cgltf** (одно-хедерная, C, движко-
   независимая, тестируется в core против реальных байт — как Gr2). Выдаёт структуру,
   совместимую с `Gr2Mesh`, плюс skinning: `joints`/`weights` на вершину, иерархия
   костей, `AnimationClip` (кривые TRS по времени).
2. **Расширить меш-тип** до опциональных `joints/weights` + скелет (или ввести
   `SkinnedMesh` рядом с `Gr2Mesh`, общий путь заливки).
3. **Скелетный скиннинг в рендере**: `vs_model` уже несёт нормаль/тангент; добавить
   вариант с матрицами костей (палитра в uniform/буфере) — **изолированным шейдером**,
   чтобы не задеть общий sprite-путь (вода/тени), по тому же принципу, что и нормалки
   земли.
4. **Материалы**: glTF PBR (baseColor + normal + metallicRoughness) ложатся на уже
   готовый `s_nrm` + диффуз; metallic/roughness — опционально позже.
5. **Размещение сущности**: RoM-модель как альтернативный «спрайт» актёра (переключатель
   2D-спрайт ↔ 3D-модель по job/mob id), либо как отдельная 3D-сущность на карте.

Клиент грузит **.glb** (свободные папки перекрывают GRF — HD/3D-контент кладётся
поверх, см. [hi-res-textures.md](hi-res-textures.md)); никакого Unity-рантайма.
